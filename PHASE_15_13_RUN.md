# Phase 15.13 Runbook — Bank Reconciliation & Check Intelligence

## Goal

Turn the existing checks/banking module into a professional control surface for check-heavy auto-parts stores without changing posted accounting journals during reconciliation.

## Delivered

- Migration `018_bank_reconciliation_intelligence.sql`.
- Weighted selected-check maturity averaging (راس‌گیری).
- 7–180 day check cash calendar, maturity buckets, projected bank balance and owner/accountant risk dashboard.
- Customer receivable-check exposure and low/medium/high risk indicators based on overdue and bounced history.
- Bank statement import with store/tenant ownership validation and exact duplicate fingerprint protection.
- Reconciliation candidates from the selected bank GL account using direction, available unmatched amount and ±14 day proximity.
- Full and partial matching.
- Reconciliation match history and audited undo/reopen.
- Reconciliation never mutates the accounting journal; it links statement lines to existing journal entries only.
- New `/store/finance-control` UI for dashboard, maturity average and reconciliation workflows.

## Acceptance

Run after applying the migration:

```bash
./ops/rc-static-check.sh
git diff --check
go test ./internal/finance
cd web && npm run build
```

Then smoke-test:

1. Select multiple open receivable checks and calculate weighted maturity.
2. Repeat for payable checks; mixed directions must be rejected.
3. Import a bank statement line twice; the exact duplicate must be skipped.
4. Match a line fully to a compatible bank journal entry.
5. Partially match another line and verify the remaining amount.
6. Undo a match and verify the statement line reopens while the accounting journal remains unchanged.
7. Verify another store/tenant cannot access the statement line or its matches.
8. Check the 90-day cash calendar and customer risk table.

## Rollback

Application rollback can be done with the Git commit generated by the Easy Apply package. Database rollback for migration 018 should only be done in a controlled environment after confirming no production reconciliation data must be retained.
